# Конфигуратор — два экземпляра по окружению, а не переключатель внутри UI

## Решение
Один код `etl_config_app`, два процесса: TEST на :5555 (база `test`, значения по умолчанию) и PROD на :5556
(`ETL_CONFIG_DB_NAME=etl_prod`). Окружение задаётся только переменными при запуске, в интерфейсе видна
несменяемая метка (`TEST / test` синяя, `PROD / etl_prod` красная). Переключателя TEST/PROD внутри UI нет.

## Почему
До 2026-09-09 подключение было захардкожено на `test` (`dao.py`), PROD-регистры создавались миграциями и UI их
не видел. Переключатель внутри одного процесса — это один клик до Save/Sync не в той базе. Отдельный процесс с
красной меткой на каждой странице делает окружение очевидным и позволяет держать разные политики
(`ETL_CONFIG_ALLOW_DESTRUCTIVE`, `--reload` только на TEST).

## Что это потребовало
- PATCH-семантика Save таргета; FK по правилу движка; контрактные system-колонки в DDL (см.
  [[Регистр order строится от шапки документа с UNION табличных частей, а не от AccumRg]]).
- Отказы 409 вместо тихих каскадов: удаление union/источника, питающих таргет; удаление регистра с данными;
  переименование таблицы и колонок на таблице с данными.
- Destructive DDL через UI выполняется только при `ETL_CONFIG_ALLOW_DESTRUCTIVE=1` (по умолчанию выключено везде).
- Read-only `GET /api/registers/{id}/sync-plan` — dry-run плана; ожидание для PROD — NO ACTION по всем таргетам.

Runbook: `etl_config_app/RUNNING.md`.
