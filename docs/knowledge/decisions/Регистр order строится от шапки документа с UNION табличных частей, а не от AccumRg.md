# Регистр order строится от шапки документа с UNION табличных частей, а не от AccumRg

## Решение
PROD `orders` ← `_Document271` (только `_Posted = 0x01 AND _Marked = 0x00`); `order_positions` ← `_VT4708` Товары ∪ `_VT4746` Услуги
с технической колонкой `vt_kind` ('product' | 'service'). Natural key позиций — `(recorder, recorder_type, vt_kind, line_no)`:
номера строк товаров и услуг пересекаются (131 пара за один день). Имя шапки — `orders`: `order` зарезервировано в SQL,
а движок пишет `public.{table}` без кавычек. FK позиций — `order_id`; валидатор ищет `{dim}_id`, затем без `s`.

## Почему не `_AccumRg16915`
Регистр ЗаказыПокупателей движут четыре типа документов (271, 415, 254, 275) и он содержит только товары — услуги потерялись бы.
Старый TEST-конфиг `order` (Union пяти документов над регистром, 19 несуществующих колонок из meta API) не переносился.

## Пайплайн `document_with_vt`
Новый код в ядре не потребовался: это generic-путь QueryBuilder — target шапки с `source_id` на header, target позиций с `union_id`
на два detail (INNER JOIN на `_IDRRef`), константы через `is_expression` (`CAST(271 AS int)`, `'product'`). DataChecker
(overlap 5 мин, tail 15 суток, missing-delete) переиспользован как есть: `retail.orders.document_uid` → `_IDRRef`.
В DAG `document_with_vt` — тот же runner ETLEngine с `requires_retail`.

## Что исключено и почему
Пустые за 2026: акциз, Эврика_Предоплата, ДатаОтгрузки, автоскидки, МетодОплаты, УсловиеПродаж, ДокументОснование.
PII (телефон, ФИО, ИИН, дата рождения) не грузим. Бонусы у услуг заказа не заполняются — только у товаров
(`_Fld26962`/`_Fld26963`, подтверждено сверкой с sales). `_VT25124` (оплаты: Эврика_СпособыОплаты, IdTerminal, сумма,
транзакция) и `_VT26994` (акции по строкам) — следующее расширение, не позиции.

## Результат 2026-09-03
История 2026-02-01..2026-09-03: 420 307 заказов, 593 780 позиций; сверка с 1С по месяцам (docs, строки по видам, суммы, НДС,
количество, сумма шапки) — в ноль; все 11 FK разрешены, dangling/дублей/NaN 0. Покрытие `sales.raw_refs.zakaz` заказами 99,78 %.
Наблюдение по данным 1С: у 30 заказов из 420 тыс. `СуммаДокумента` ≠ Σ строк (25 — организация с префиксом 87); PROD повторяет 1С.
663 заказа без строк (сумма 0).
