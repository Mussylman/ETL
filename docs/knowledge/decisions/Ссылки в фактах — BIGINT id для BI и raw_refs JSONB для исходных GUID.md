# Ссылки в фактах: BIGINT `*_id` для BI и `raw_refs` JSONB для исходных GUID

## Решение
В таблицах фактов/регистров (эталон — `public.sales` и `public.sales_positions` на PROD `etl_prod`) ссылки хранятся так:

1. **`*_id BIGINT`** — только на существующий справочник `dim_*` или существующий регистр (`doc_sale_id` → `sales.id`, `sales_id` → `sales.id`). Это единственные ссылочные колонки, которые видит BI.
2. **`raw_refs JSONB`** — все исходные ссылки 1С как приехали: справочник → `"kontragent": "<guid>"`, полиморфная ссылка/документ → `"doc_sale": {"type": 415, "uid": "<guid>"}`. Пустая ссылка 1С (`00000000-…`) в raw_refs не пишется.
3. **Ссылки на регистры, которых в DWH ещё нет** (`zakaz` → будущий регистр `order`, `_Document271`), живут **только в raw_refs**. Фейковые `zakaz_id` не заводятся.
4. **Технические ключи** (`recorder`, `recorder_type`, `line_no`, `period`) остаются отдельными колонками — на них upsert, добор хвоста, missing-delete и сверка.
5. **GUID → BIGINT через hash не делаем.** `id` выдаёт только справочник (stub-строка `ON CONFLICT (guid) DO NOTHING`), один раз и навсегда.

## Почему
- Раньше рядом с каждым `*_id` лежал дубль-uuid (`kontragent`, `dogovor_uid`, `doc_sale_uid`+`doc_sale_type`, …) — 20 колонок, которые BI не нужны, а resolver читал их как промежуточный слой. Один JSONB с GIN-индексом закрывает ту же диагностику («какой guid не разрешился») без раздувания схемы.
- Полиморфные ссылки (`doc_sale`, `zakaz`) требуют пары type+uid; в JSON это естественно, в колонках — две колонки на ссылку.
- Hash-ключ оторвал бы `id` от справочника: при появлении строки в `dim_*` пришлось бы менять ключ в фактах. Stub-паттерн даёт стабильный id сразу, имя доезжает позже (см. [[guid принадлежит 1С]]).

## Как устроено
- Мэппинги в `etl_meta.column_mappings` целятся в `raw_refs.<key>` или `raw_refs.<key>.uid|type`; движок (`_pack_raw_refs` в `etl_engine.py`) пакует их в один dict перед загрузкой. `raw_refs` — SYSTEM-колонка для QueryBuilder и Sync (не дропается).
- `post_load_sql` таргета делает stub в `dim_*` из `raw_refs->>'x'` и проставляет `*_id`; `doc_sale_id` — self-ссылка или id исходной реализации, если она в `sales`.
- Валидатор после full_period: `raw_refs ? 'x' AND x_id IS NULL` должно быть 0 для каждого `x`, у которого есть `dim_x`.
