# Custom Python Transform для вычисляемых колонок

## Проблема
Часть колонок в target-таблицах — не прямой маппинг из 1С, а бизнес-логика с условиями и доступом к нескольким колонкам одной строки.

Пример: `sales_with_vat = Стоимость если НДС > 0 иначе Стоимость × 1.12`.
Или: `earned_bonuses = знак_документа × Эврика_Бонусы`, где знак зависит от `_RecorderTRef` + `ВидОперации`.

SQL expression в конфигураторе — слишком ручная работа для аналитиков: нужно писать CASE по каждому правилу, пересобирать при изменении. Вычисление на клиенте БД тоже плохо — логика вшита в пайплайн, а не в конфигурацию.

## Решение
Новый тип трансформации `custom_python`. Функции пишет разработчик один раз, аналитик выбирает имя функции из реестра.

## Как работает
1. Функции живут в `dags/core/transform/custom.py`, реестр `CUSTOM_TRANSFORMS` — `{имя: {function, description, target_type, uses_columns}}`.
2. В `column_mappings` колонка имеет `transform_type = 'custom_python'`, `transform_params = {"function": "sales_with_vat"}`.
3. `TransformUtils.apply_transforms` на этапе transform разделяет column-level (binary, fix_year) и row-level (custom_python). Custom'ы применяются через `df.apply(..., axis=1)` — каждая функция получает строку как dict.
4. UI предоставляет endpoint `/api/custom-transforms` (реестр для dropdown) и `/api/registers/{id}/add-computed-column` (добавление колонки через UI).

## Текущий реестр (7 функций)
- `sales_with_vat` — стоимость с НДС 12%
- `sales_without_vat` — стоимость без НДС с корректировкой бонусов после 2022-10-12
- `earned_bonuses`, `used_bonuses` — бонусы со знаком по типу документа
- `margin` — стоимость минус стоимость без скидок
- `unit_price` — цена за единицу
- `discount_percent` — процент скидки

## Почему не SQL expression
- SQL expression требует ручной сборки CASE при каждом изменении правила.
- Доступ к нескольким колонкам и `datetime` сравнениям неудобен в expression.
- Функция один раз тестируется разработчиком, дальше используется через имя.

## Почему не DuckDB pre_load_sql
- `pre_load_sql` — для агрегаций и дедупликации целого датасета.
- Вычисляемая колонка — свойство строки, а не набора строк. Row-level transform правильное место.

## Ограничения
- `df.apply(axis=1)` медленнее векторных операций pandas. Для тяжёлых трансформаций на миллионных датасетах переписывать на векторный вариант отдельно.
- `uses_columns` указывает, какие колонки нужны функции — это декларативно, но не проверяется автоматически. Если колонку удалили из маппинга — функция упадёт на `.get()` с дефолтом 0.
- Функции чистые: принимают row (dict), возвращают значение. Без внешних вызовов, без состояния.
