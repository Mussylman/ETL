# Упавший инкремент оставляет шапки без позиций и двигает watermark — документы теряются навсегда

## Симптом
Сверка PROD с 1С после 03.09 расходится каждый день: 145 продаж и ~90 заказов, у которых в DWH есть
шапка, но **ноль позиций**, хотя в 1С строки есть. Минуты загрузки этих шапок совпадают один в один с
упавшими прогонами инкремента: deadlock'и 09.09 17:10, 11.09 13:10, 13.09 15:20/20:20, 14.09 13:20/15:00
и обрыв сети к retail/MSSQL 10.09 11:25–12:52 (`connection refused`, DB-Lib 20009).

## Механизм
Таргеты грузятся по очереди, каждый в своей транзакции. Dim-таргет (шапка) коммитится первым **вместе с
`retail_updated_at`**, fact-таргет (позиции) падает. Дальше два штатных механизма работают против нас:
1. watermark = `MAX(retail_updated_at)` по шапкам → он уже уехал за сигналы этих документов; retry через
   2 минуты берёт окно позже них;
2. добор хвоста ищет uid, которых **нет в dim** — а шапка есть → документ никогда не перечитывается.
Тот же эффект от любой ошибки между таргетами, не только deadlock.

## Решение
`ETLEngine._run_incremental`: на пути ошибки вызывается `_cleanup_incomplete_headers(changed_uids, run_started_at)` —
удаляет шапки, записанные этим прогоном (`etl_updated_at ≥ старт прогона`, `recorder ∈ changed_uids`) и не имеющие
строк в fact (`NOT EXISTS … p.<fk> = d.id`, FK по правилу `{dim}_id` / без «s»). Удалённая шапка становится
«отсутствующей», и хвост перечитает документ целиком следующим тиком. Только путь ошибки — легитимно пустые
документы успешных прогонов (663 пустых заказа) не трогаются. Dry-run на реальных падениях: 61/61 (sales 14.09 13:20),
25/25 (order 14.09 15:00).

Данные починены повторным `full_period` поверх (upsert идемпотентен, удаление исчезнувших строк в post_load) —
см. лог сессии. Триггер deadlock'ов закрыт цепочкой sales → order в DAG
([[Параллельные инкременты sales и order ловят deadlock в общих dim и post_load — ETLEngine-таски идут цепочкой]]).

## Что не закрывает инкремент вообще (нужна пересборка)
Документы без сигнала retail (чеки магазинов UCB Infinity Атырау / Шымкент, возвраты без чека, ОтчётКомитенту)
и правки строк в 1С без нового сигнала. Для них — ночное «закрытие дня»: `full_period` за D-2..D + `sales_recon --strict`.
