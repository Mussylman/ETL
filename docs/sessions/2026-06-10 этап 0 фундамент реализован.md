# Сессия 2026-06-10: Этап 0 (фундамент) реализован

Реализация плана из [[Wizard'ы по типам 1С строятся над единым RegisterSpec и одним writer]].

## Фаза 0.1 — сетка безопасности (новые файлы)

- `etl_config_app/register_spec.py` — RegisterSpec (Pydantic v2), ссылки по code,
  валидатор контракта validate_spec()
- `etl_config_app/spec_writer.py` — write_spec(): одна транзакция, схема
  параметризуется, replace-семантика
- `etl_config_app/spec_reader.py` — etl_meta/etl_test → RegisterSpec
- `etl_config_app/tests/` — mirror_loader (дословное зеркало SQL ConfigLoader),
  golden_sales_test, validator_test (17 шт.), sql_snapshot (регресс-гейт),
  sync_ddl_test (16 шт.)

ВАЖНО: живая etl_meta была ПУСТА — эталон sales материализуется из
`_pending_sales_rebuild.sql` в схему **etl_test_ref** (изолированно), round-trip
пишется в **etl_test**. Когда sales появится в бою: `--schema-ref etl_meta`.

## Фаза 0.2 — Sync-DDL + 6 правок движка (все под гейтом)

Гейт после каждого шага: golden-тест + SQL-снапшот sales идентичен baseline
(`tests/snapshots/sales_sql.json`). Все прогоны зелёные.

Sync-DDL (`dao.compute_sync_plan`): PK(id) — BIGSERIAL или натуральный id из
маппингов; UNIQUE(upsert_keys) с предварительной проверкой дублей (дубли →
destructive → confirm/recreate); updated_at у dimension; FK-колонка
`{dim_table}_id` у fact с REFERENCES. Идемпотентно (повторный план пуст).

Правки движка:
1. `etl_engine._get_watermark_table()` — watermark из dim-target, fallback public.sales
2. mode='full' — без обязательных дат (full_period не изменился)
3. `register_sources.period_column` (миграция 004 применена к живой etl_meta):
   NULL→'_Period' (legacy), ''→без фильтра, '_Date_Time' для документов;
   models + ConfigLoader + QueryBuilder + mirror + spec-слой
4. missing-delete: ключ = target.upsert_keys[0], fallback 'recorder'
5. QueryBuilder._normalize_join_type() — фикс «INNER JOIN JOIN»
6. transform invert_bool (для _Folder: 0x00=группа)
