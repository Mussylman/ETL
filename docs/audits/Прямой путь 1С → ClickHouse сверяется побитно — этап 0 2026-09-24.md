# Прямой путь 1С → ClickHouse сверяется побитно — этап 0

Проверка, можно ли сверять ClickHouse **напрямую с 1С**, минуя PostgreSQL. Без этого
прямой путь нельзя было бы переводить в production: сверять было бы нечем.

## Результат по факту продаж: PASS

`_AccumRg17844` (регистр продаж) против `analytics_poc.fact_sales_positions`,
13 метрик: строки, документы, контрольная сумма по бизнес-ключу и guid номенклатуры,
`sum` и `sum` квадратов по пяти мерам. Совпало **побитно** на четырёх месяцах разных
лет — 201412, 201906, 202212, 202606.

Контрольная сумма включает guid номенклатуры, то есть проверена вся цепочка
`ссылка 1С → stub → id → справочник`. Сдвиг года +2000 и порядок байт `_IDRRef`
воспроизводятся в T-SQL точно так же, как в `core.transform.binary_to_uuid`:
uuid = `b12..b15-b10b11-b8b9-b0b1-b2..b7`.

## Найденные дефекты

**MSSQL-хеш считал UTF-16LE.** `HASHBYTES` над `nvarchar` хеширует UTF-16LE, ClickHouse
и PostgreSQL — UTF-8. На любой кириллической строке контрольная сумма не сошлась бы
никогда. Исправлено через UTF-8-сортировку (SQL Server 2019+). Эта ветка ни разу не
исполнялась до этапа 0 — дефект найден до попадания в сверку.

**MSSQL-приведение обрезало строки до 64 символов** — исправлено на 4000.

## Unicode на справочнике

`_Reference123` против `dim_nomenklatura`: после выравнивания обрезки пробелов совпали
130 938 из 130 958, из них 88 264 с кириллицей. Кодировка проходит чисто.

Оставшиеся 20 — **не ошибка сверки, а данные**:

- **переименования в 1С, не дошедшие до DWH** («Dauscher»/«Deutscher», «Плоттер»/
  «Принтер», «Не использовать»). Инкремент справочников их не подхватывает — это
  существующий дефект качества, прямой путь со sweep его закроет;
- **неразрывный пробел `\xa0`**: Python `str.strip()` его убирает, SQL `LTRIM/RTRIM` —
  нет. Одно и то же «обрезать пробелы» в двух системах означает разное.

## Скрытое преобразование

`load_dim_from_config` делает `v.strip() or None` (строка 364), но в `column_mappings`
у `_Description` стоит `transform_type = NULL`. Преобразование есть в коде, но не в
конфиге — прямой путь обязан сделать его явным.

## Следствие для проектирования сверки

Колонки, прошедшие Python-преобразование, **нельзя сверять SQL-выражением на источнике**:
`strip()` и `TRIM` расходятся на `\xa0`. Сверка двухуровневая:

- **независимая** против 1С в SQL — для того, что воспроизводимо в SQL точно: ключи,
  ссылки, меры, даты. Ловит ошибки извлечения;
- **целостности загрузки** — отпечаток считается в Python по уже преобразованным
  строкам потока и сравнивается со staging ClickHouse. Покрывает все колонки.

## Связь «ссылка → справочник» не задана декларативно

`transform_params.dim` не задан **ни у одного** мэппинга. Связь живёт только в тексте
`post_load_sql`. Текст однороден (`INSERT INTO public.dim_X (guid) SELECT DISTINCT
(raw_refs->>'key')`) — пары извлекаются механически, включая неочевидную
`gruzopoluchatel → dim_kontragent`.

## Блокеров нет

Всё найденное — исправимо или является проектным решением. Прямой путь сверяется.
