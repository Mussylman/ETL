⚠️ Сложная бизнес-логика при загрузке

Есть колонки (например sales_with_vat), которые зависят от типа документа, даты, полей шапки И табличной части. В 1С это был CASE WHEN запрос. Если считать в Power BI — визуалка тормозит. Нужно считать при загрузке.

Пример логики из 1С:

    ТОГДА ВЫБОР
      КОГДА Регистратор ССЫЛКА Документ.РеализацияТоваровУслуг

2 Два варианта решения
Вариант 1

SQL Запросник

Аналитик пишет SQL выражение в конфигураторе

Как работает

  • На странице source — поле "SQL выражение"
  • Аналитик пишет CASE WHEN на диалекте MSSQL
  • ETL Engine подставляет в SELECT запрос
  • Для каждого типа документа — своё выражение
В конфигураторе (для doc_476 ЧекККМ): target: sales_with_vat type: expression CASE WHEN _Date_Time >= '4022-10-12' AND h._Fld_SendABM = 0x01 AND h._Fld_BonusAmount > 0 THEN ISNULL(vt._Fld_Written, 0) + _Fld17853 ELSE _Fld17853 END
Плюсы Аналитики знают SQL
Гибко — любая логика
Не нужен Python
Минусы Для каждого документа свой CASE
Сложные выражения трудно отлаживать
Нужно знать MSSQL имена полей
Вариант 2

Custom Transform

Python-функция, выбирается в маппинге как transform

Как работает

  • Разработчик пишет Python-функцию один раз
  • Регистрирует как новый transform type
  • Аналитик в конфигураторе выбирает из списка
  • ETL Engine применяет функцию к каждой строке
Python функция (один раз): def sales_with_vat(row, params): cost = row.get("cost", 0) bonus = row.get("bonus_written", 0) doc_type = row.get("doc_type", "") if row["date"] >= 2022-10-12 and row["send_to_abm"]: if "Возврат" in doc_type: return -1 * bonus + cost elif bonus > 0: return bonus + cost return cost В конфигураторе: transform: custom:sales_with_vat
Плюсы Логика в одном месте
Легко тестировать (unit tests)
Аналитик просто выбирает из списка
Минусы Нужен Python-разработчик
Новая функция = деплой
Медленнее чем SQL (row-by-row)
